# Known limitations

As of 2026-08-02:

- Live trading is disabled: all seven release flags are false, Live execution worker desired count is zero, and required legal/advisory/App Store/Robinhood production approvals and credentials are not present.
- The authenticated Paper API and native app can retrieve the currently applicable, versioned legal documents and record consent. The repository intentionally contains no counsel-approved, production-published document set; Paper fails closed when a required approved document is absent, and Demo fixtures never constitute production language or consent for Live.
- Demo pairing is local and accepts `SAFE-482K`; it never contacts Robinhood. Durable same-user, one-time pairing and the one-tap mobile initiation boundary are implemented: **Connect to Robinhood** creates or resumes a pairing, requests a server-provided and validated Robinhood OAuth destination, opens it in `ASWebAuthenticationSession`, and accepts only a token-free result/pairing return. `verification_pending` is not Connected: the app re-fetches canonical server status until broker sync verifies the Agentic Account, required capabilities, and a fresh snapshot and atomically reports `connected`. The public `https://agent.robinhood.com/mcp/trading` address is a Streamable HTTP MCP resource, not a browser setup page. The Paper host has a dynamically registered public PKCE client and an isolated connector whose per-authorization token records are individually encrypted; deployments without that connector still fail closed.
- WHOX does not impose a device restriction on Robinhood's generated authorization URL. It opens the validated, PKCE-bound URL in `ASWebAuthenticationSession` and preserves that exact short-lived URL through a canceled presentation so the user can reopen it while canonical server-status polling continues. Explicit Cancel invalidates it. Robinhood currently documents that first-time Agentic Account creation and agent authentication require a desktop browser; returning users remain subject to the provider's current device policy.
- Paper readiness covers durable identity, onboarding, rate limiting, and Apple verification. A missing approved Robinhood connector disables only the broker-authorization capability with a fail-closed `503`; it does not relabel the whole API as unavailable or prevent Sign in with Apple. Readiness never implies broker authorization or trading availability.
- Administrative authentication is simulated only in Demo. Both mock auth outside Demo and the OIDC selection fail closed; organization SSO, phishing-resistant MFA, managed-device policy, server RBAC/API integration, and durable administrative auditing are not implemented yet.
- StoreKit products/prices remain fixtures until created and approved in App Store Connect. The Paper API now has official Apple signed-transaction verification and a durable App Store Server Notifications V2 handler, but deployment still requires the approved product records, App Apple ID, current Apple root bundle, dedicated database credential, HTTPS notification URLs, and successful sandbox/test-notification evidence. Buying a plan never provides broker options approval.
- Robinhood tool availability/schema is runtime-discovered and may change. A listed tool is not assumed present; dependent features disable safely. Options/complex strategies remain independently gated by broker capability, user approval, risk, legal, and release flags.
- Demo market and portfolio data are synthetic fixtures and cannot substantiate expected results. Paper's persistent API/session/pairing adapters, iOS assembly, deterministic shared plan cycles, immutable Hermes research artifacts, tenant-isolated fan-out, approved-provider quote-refresh boundary, receipt-bound broker-account hydration, and Foundation Equity v1 strategy-to-proposal/execution pipeline are implemented and database-tested. The default Compose profile still keeps broker authorization disabled; an explicitly configured Paper composition can inject the isolated Robinhood connector. Paper still requires approved market-data and production step-up composition before trading workflows are complete. The other six catalog strategies intentionally fail closed in the persistent pipeline.
- Hermes is one logical deterministic request per canonical plan cycle, not an external exactly-once guarantee. Durable retries can repeat the network call with the same request identifier; the remote profile must remain stateless and tool-free, and PostgreSQL accepts only one immutable digest-bound artifact. Hermes receives only the centrally published, bounded public plan quote context—never tenant identity, accounts, portfolios, holdings, policies, approval state, orders, or credentials.
- Paper Hermes startup requires the exact canonical URL `https://treasury-bot.whox.ai/v1`, exact model `treasury-bot`, an orchestrator-only managed and rotated key, and exact `HERMES_RESEARCH_PROFILE_TOOLS_DISABLED=true` attestation after the remote profile has actually been verified. Any key exposed to a user, prompt, chat, client, log, or ticket is compromised and must be revoked and replaced without displaying or reusing it.
- Paper order reconciliation requires a fresh quote from an explicitly approved provider and defers resting, stale, halted, restricted, or otherwise blocked orders instead of fabricating a fill. Paper order cancellation and agent/global pause paths atomically terminalize eligible unsubmitted work, release reservations, halt queued execution, and preserve audit/notification state. These controls are simulation safety boundaries, not evidence of production broker execution or external launch readiness.
- Performance methodology requires compliance/legal approval before public presentation. Backtest/Paper/Live data must remain separate.
- Terraform is a deployable reference boundary but still requires account-specific remote state, DNS/certificates, image digests, IAM review, secret bootstrap/rotation, budgets, provider quotas, and a reviewed plan before apply.
- The APNs provider, token encryption, privacy-policy lookup, invalid-token cleanup, and replay protection are implemented and tested, but real APNs delivery still requires Apple credentials and provisioning. The API now denies proposal approval, agent resume/recovery, broker disconnect, account deletion, and risk-policy relaxation without a fresh exact-context server-verified step-up proof and durably consumes proof identifiers once. Native request composition, server-canonical action/resource preview, and fail-closed proof propagation are implemented; the production App Attest cryptographic provider and server verifier are not, so these actions intentionally remain unavailable outside a test-composed adapter. Sign in with Apple registration, email, status/support endpoints, WAF tuning, alert routing, backup destinations, and subprocessors still require approved accounts, adapters, or secrets.
- The retained 125-image iPhone/iPad visual matrix covers the complete Demo page set, including dark mode and Accessibility XXXL. Authenticated Paper rendering has build, unit, and contract coverage, but the page-level Paper matrix must be repeated against production-like staging data and approved provider adapters before App Store submission; the repository does not yet prove visual correctness for every externally integrated Paper state.

No limitation authorizes an unofficial broker API, browser scraping, stored Robinhood password, fabricated fill/capability/data, weakened risk control, hidden demo behavior, or model-direct order placement.
